```ts twoslash title="main.ts"
// Twoslash runs TypeScript 6, which cannot run a content mapper: get_user.d.sql.ts is the module
// Porg's mapper returned for get_user.sql (tsc --runExternalCode, against the schema below).
// @allowArbitraryExtensions
// @filename: get_user.d.sql.ts
import type { Query } from "porg";
export type Params = { id: number };
export type Row = { id: number; name: string; email: string | null };
export declare const sql: "select id, name, email from users where id = :id\n";
export declare const params: readonly ["id"];
declare const query: Query<{ id: number }, { id: number; name: string; email: string | null }, "maybeOne", "postgres">;
export default query;
// @filename: guard.ts
import getUser from "./get_user.sql";
// @ts-expect-error: fails the build if the porg types stop resolving and the query becomes `any`.
const typed: string = getUser;
// @filename: main.ts
// ---cut---
import postgres from "postgres";
import getUser from "./get_user.sql";

const sql = postgres(process.env.DATABASE_URL!);

const user = await getUser.run(sql, { id: 1 });
```

Every type above comes from the database.

## How it works

Porg is a [content mapper](https://github.com/microsoft/typescript-go/pull/4712), a feature new in TypeScript 7.1: a package that turns a file TypeScript does not know into a typed module, in the type checker and in the editor. Bundlers have loaded `.sql` files for years, and content mappers are the missing half, so a loader is now type safe from end to end.

```text
get_user.sql  →  Porg  →  your database  →  { id: number; name: string; email: string | null } | null
```

To type a query, Porg sends it to your running database, which prepares it without running it. The database reports:

- the parameter types
- the column types
- nullability, from `NOT NULL` and outer joins
- the row count, from primary and unique keys

Porg connects through your project's `postgres`, `pg` or `mysql2` if it has one, and otherwise through a client of its own, and keeps each answer in `.porg/` until the schema changes.

## Setup

Install Porg and point it at your database, then add it to each tool that loads your code.

### Install

```sh
npm install porg
npm install -D typescript@next   # content mappers are in the TypeScript 7.1 dev builds
```

Porg needs Node 24 or later. It reads `DATABASE_URL` from the environment, or from `.env.local` or `.env` next to `package.json`:

```sh title=".env"
DATABASE_URL=postgres://localhost:5432/app   # mysql://… for MySQL, file:./app.db for SQLite
```

Other settings go in `.porg.yaml`: see [The project file](/details#the-project-file).

### TypeScript

Add Porg to `tsconfig.json`:

```jsonc title="tsconfig.json"
{
  "compilerOptions": { /* ... */ },
  "contentMappers": [ // [!code ++]
    { "package": "porg", "extensions": [".sql"] } // [!code ++]
  ] // [!code ++]
}
```

Type-check with `--runExternalCode`. Without the flag, `tsc` ignores content mappers.

```json title="package.json"
{
  "scripts": {
    "typecheck": "tsc --noEmit --runExternalCode"
  }
}
```

### Runtimes

A preload turns each `.sql` import into a module as it loads:

```sh
node --import porg/register main.ts
```

Bun and nub read the preload from their config files, so no flag is needed:

```toml title="bunfig.toml"
preload = ["porg/register"]
```

```jsonc title="nub.jsonc"
{
  "preload": ["porg/register"]
}
```

## Basic usage

Write the query in a `.sql` file:

```sql title="get_user.sql"
select id, name, email from users where id = :id
```

Import it, and run it with a client from your driver:

```ts title="main.ts"
import postgres from "postgres";
import getUser from "./get_user.sql";

const sql = postgres(process.env.DATABASE_URL!);

const user = await getUser.run(sql, { id: 1 });
// { id: number; name: string; email: string | null } | null
```

The query has a few more members:

```ts
import type { Params, Row } from "./get_user.sql"; // its parameter and row types

const get = getUser.with(tx);        // bind a client once, such as a transaction
await get({ id: 1 });

getUser.runSync(db, { id: 1 });      // better-sqlite3, node:sqlite and bun:sqlite answer synchronously

getUser.sql;                         // the statement as written
getUser.params;                      // ["id"]
getUser.cardinality;                 // "maybeOne"
```

## Type inference

Porg puts no limits on the query: any syntax, any built-in function, *the full expressive power of your SQL dialect*. Each example shows a statement and the types Porg infers: the parameters, and what `run` resolves to.

### Parameters

```sql title="search.sql"
select id, name from users
where name like :pattern and role = :role
```

```ts
type Params = { pattern: string; role: "admin" | "member" };
type Result = { id: number; name: string }[];
```

### Nullability

```sql title="user_posts.sql"
select u.name, p.title, coalesce(p.title, '') as label
from users u
left join posts p on p.user_id = u.id
```

```ts
type Result = {
  name: string;          // not null in the table
  title: string | null;  // the outer side of a left join
  label: string;         // coalesce with a non-null default
}[];
```

### Enums, arrays and dates

```sql title="profiles.sql"
select role, tags, created_at from users
```

```ts
type Result = { role: "admin" | "member"; tags: string[]; created_at: Date }[];
```

### Row count

```sql
-- get_user.sql
select * from users where id = :id

-- count_users.sql
select count(*) from users

-- list_users.sql
select * from users

-- delete_user.sql
delete from users where id = :id
```

```ts
type GetUser = Row | null;  // a primary-key match, or limit 1
type CountUsers = Row;      // an aggregate without group by
type ListUsers = Row[];     // anything else
type DeleteUser = void;     // a write without returning
```

### Returning

```sql title="create_user.sql"
insert into users (name, email) values (:name, :email)
returning id
```

```ts
type Params = { name: string; email: string | null };
type Result = { id: number };
```

### Common table expressions

```sql title="post_counts.sql"
with counts as (
  select user_id, count(*)::int as posts from posts group by user_id
)
select u.name, coalesce(c.posts, 0) as posts
from users u
left join counts c on c.user_id = u.id
```

```ts
type Result = { name: string; posts: number }[];
```

### Nested JSON

```sql title="user_with_posts.sql"
select u.id, u.name,
  coalesce((
    select jsonb_agg(jsonb_build_object('id', p.id, 'title', p.title, 'at', p.published_at))
    from posts p where p.user_id = u.id
  ), '[]') as posts
from users u
where u.id = :id
```

```ts
type Params = { id: number };
type Result = {
  id: number;
  name: string;
  posts: { id: number; title: string; at: string | null }[];
} | null;
```

## Supported drivers

Porg imports no driver. Pass `run` the client of any of these:

- Postgres
  - `pg`
  - `postgres` (postgres.js)
  - `Bun.sql`
  - `@electric-sql/pglite`
  - `@neondatabase/serverless`
  - `pg-promise`
  - `@vercel/postgres`
- MySQL
  - `mysql2`
  - `mariadb`
  - `@planetscale/database` (1.x)
- SQLite
  - `better-sqlite3`
  - `node:sqlite`
  - `bun:sqlite`
  - `@libsql/client`
  - Cloudflare D1
  - `sqlite3`
  - `sqlite`

A transaction, savepoint or connection from these clients works too: see [Transactions](/details#transactions-and-synchronous-drivers).

The tables show what most drivers return. Porg reads your driver from `package.json` and follows it where it differs:

- mariadb: `BIGINT` is a `bigint`
- PlanetScale: dates and `BIGINT` are a `string`
- PGlite: `bigint` is a `number`, or a `bigint` above 2^53
- libsql: `BLOB` is an `ArrayBuffer`
- Cloudflare D1: `BLOB` is a `number[]`

If you set your driver up to decode a type another way, say so in `.porg.yaml`:

```yaml title=".porg.yaml"
types:
  dates: string        # Date, string or temporal
  bigint: bigint       # string, number or bigint
  decimal: number      # string or number
  json: string         # parsed or string
  binary: Buffer       # Uint8Array, Buffer, ArrayBuffer or number[]
```

Which driver option needs which setting: see [Driver settings](/details#driver-settings).

## Dialects

Postgres is the reference dialect. MySQL and SQLite type less: see [Dialect limits](/details#dialect-limits).

### Postgres

Porg prepares the statement on the server and reads the description of its parameters and columns. It then reads the catalog for `NOT NULL`, keys and enum labels.

| What | Where it comes from |
| --- | --- |
| Parameter types | the server's description of the prepared statement |
| Column types | the server's description; an enum as its labels, a domain as its base type |
| Nullability | `NOT NULL` in the catalog, outer joins, the expressions |
| Row count | primary and unique keys, aggregates, `limit 1`, `returning` |
| Nested JSON | `jsonb_build_object`, `jsonb_agg` and `to_jsonb`, typed from their arguments |

### MySQL

Porg prepares the statement on the server, which reports the column types, `NOT NULL`, and a type for each parameter from its context. Porg adds the row count and the shape of JSON built in the statement.

| What | Where it comes from |
| --- | --- |
| Parameter types | the server's prepare |
| Column types | the server's prepare |
| Nullability | the server's `NOT NULL` flag |
| Row count | primary and unique keys, aggregates; a write is `void` (MySQL has no `returning`) |
| Nested JSON | `json_object` and `json_arrayagg`, typed from their arguments |

### SQLite

Porg reads the schema from the database file and prepares the statement against its own copy of SQLite. SQLite then reports where every column and parameter comes from.

| What | Where it comes from |
| --- | --- |
| Parameter types | where SQLite places the parameter: a comparison with a column, an `insert` or `update` column, a `cast`, `limit` and `offset` |
| Column types | the declared type's affinity |
| Nullability | `NOT NULL` in the table, outer joins, Porg's table of SQLite's built-in functions |
| Row count | unique indexes and `integer primary key` |
| Nested JSON | `string` |
