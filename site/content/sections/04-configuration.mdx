## Configuration

Configure Reylo in a `.reylo.yaml` file beside `package.json`. Every key is optional:

```yaml title=".reylo.yaml"
# the dev database Reylo reads your schema from (the default)
direct_url: ${DATABASE_URL}
# the .env files Reylo reads (the default)
env: [.env.local, .env]
# an error for a parameter whose type cannot be inferred (the default)
strict_params: true
# SQL files to read your schema from instead of a database (none by default)
# schema: db/schema.sql
```

### `direct_url`

The dev database Reylo reads your schema from. It defaults to `DATABASE_URL`, and its scheme names the dialect:

```sh title=".env" tab="Postgres" tab-group="dialect"
# or postgresql://; the type check uses your pg or postgres.js
DATABASE_URL=postgres://localhost:5432/app
```

```sh title=".env" tab="MySQL" tab-group="dialect"
# the type check uses your mysql2
DATABASE_URL=mysql://root@localhost:3306/app
```

```sh title=".env" tab="SQLite" tab-group="dialect"
# or sqlite:; the path starts at package.json; no driver needed
DATABASE_URL=file:./app.db
```

Point it at a direct connection, not a pooler: describing a query through a pooler in transaction mode, such as PgBouncer's, can fail. You can interpolate other variables from your environment to construct a connection string.

```yaml title=".reylo.yaml"
# the default is ${DATABASE_URL}
direct_url: postgres://${DB_USER}:${DB_PASSWORD}@${DB_HOST}:5432/app
```

### `schema` [#schema-files]

To type your queries with no database at all, as in CI, point `schema` at your schema's SQL files. Reylo loads them into a database of its own and never connects to `DATABASE_URL`:

```yaml title=".reylo.yaml"
schema: db/schema.sql
```

Dump the schema from your dev database. On Postgres, also install PGlite, which Reylo loads it into:

```sh tab="Postgres" tab-group="dialect"
pg_dump --schema-only "$DATABASE_URL" > db/schema.sql
npm install -D @electric-sql/pglite
```

```sh tab="SQLite" tab-group="dialect"
# loaded into an in-memory SQLite, so no package is needed
sqlite3 app.db .schema > db/schema.sql
```

Or list your migrations. Reylo applies them in the order of their names and skips down migrations:

```yaml title=".reylo.yaml"
# on Prisma, prisma/migrations/*/migration.sql
schema: migrations/*.sql
```

MySQL types come from its server, so `schema` works on Postgres and SQLite only. PGlite is Postgres 18 with its contrib extensions: a schema that needs another, such as PostGIS, needs a database at `direct_url`.

### `env`

The `.env` files Reylo reads, relative to `.reylo.yaml`. The first file that sets a variable wins, and the environment wins over every file.

```yaml title=".reylo.yaml"
# the default is [.env.local, .env]
env: [.env.development, .env]
```

### `strict_params`

A [parameter whose type cannot be inferred](#a-parameter-nothing-types) is an error that says to [cast it](#casts). Set `strict_params: false` to type it `unknown` instead.

```yaml title=".reylo.yaml"
# the default is true
strict_params: false
```
